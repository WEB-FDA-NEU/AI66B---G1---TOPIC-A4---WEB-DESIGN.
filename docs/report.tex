\section{Project Overview}
\hint{3--5 sentences: who the users are, what problem the product solves, and which flow is
the core of the product. Then say what changed since Milestone 2.}

Concertly is for concert-goers who want to choose a specific seat, and for organisers who
need to sell those seats without double-booking. A fan opens a concert, picks up to 8 seats
on the seat map, and the seats are held for them for 5 minutes while they pay; paying turns the
hold into an order with one QR ticket per seat. Fans can see their orders and tickets and cancel
an order up to 24 hours before the show. Admins see revenue, sales per concert and orders on a
dashboard, and check attendees in at the gate by ticket code or from the attendee list.
The core flow is \emph{seat map $\to$ 5-minute hold $\to$ checkout $\to$ QR ticket $\to$ gate check-in}.

\textbf{What changed since Milestone 2:} a FastAPI backend on PostgreSQL replaced the mock data
for seat selection, holds, checkout, account orders/tickets, login, the admin dashboard and
check-in; an idempotent seed script loads demo data; seat holds, payment and check-in are
protected against concurrent requests. The concert list, concert detail, register and admin
concert management screens still use \cpath{js/mock-data.js} (see Section~12).

\section{System Architecture}
\hint{Show how a request travels, and say how the frontend is served: by FastAPI
\cpath{StaticFiles} (same origin, no CORS) or by Live Server on another port (CORS needed).}

\begin{lstlisting}
Browser: *.html + js/*.js            served by  python -m http.server 5500
   |  js/api.js: fetch('http://localhost:8000/api/reservations',
   |             { Authorization: 'Bearer <token from localStorage>' })
   v
FastAPI (uvicorn :8000): app/main.py -> CORSMiddleware -> routers/reservations.py
   |  Depends(get_db), Depends(get_current_user)  (app/deps.py: verify JWT)
   |  services/reservations.py: SELECT ... FROM seats ... FOR UPDATE
   v
PostgreSQL: users, concerts, zones, seats, reservations, orders, tickets
   ^
   |  background task in main.py: every 30 s releases expired seat holds
\end{lstlisting}

The frontend is plain static files served on its own port (\cpath{http.server} on 5500 or Live
Server), so the browser calls the API on another origin and FastAPI enables
\cpath{CORSMiddleware} with origins from \cpath{CORS_ORIGINS} (default \code{*}). The API base URL
is \cpath{http://localhost:8000/api} unless \cpath{window.CONCERTLY_API_BASE} is set. Every
error is returned as \code{\{"error":\{"code","message",\ldots\}\}}, and write operations run in a
transaction that is retried on deadlock or serialization failure (\cpath{services/txn.py}).

\begin{example}
\begin{lstlisting}
Browser: frontend/*.html + js/pages/*.js
   |  api.js: fetch('/api/listings?category=books', { Authorization: 'Bearer <token>' })
   v
FastAPI: main.py -> routers/listings.py -> Depends(get_session), Depends(get_current_user)
   |  SQLModel: select(Listing).where(Listing.category_id == 3)
   v
SQLite: app.db  (tables user, category, listing)
\end{lstlisting}
FastAPI serves the frontend with \code{app.mount("/", StaticFiles(directory="frontend", html=True))},
placed after all routers, so the browser and the API share one origin and no CORS is needed.
\end{example}

\section{Database Design}
\hint{An entity-relationship diagram (text or image), then the constraints that protect your data:
foreign keys, \cpath{UNIQUE}, and what \cpath{seed.py} creates.}

\begin{lstlisting}
users 1 ----< reservations >---- 1 concerts 1 ----< zones 1 ----< seats
  |               | 1                 | 1                           |  reservation_id (FK, null)
  | 1             v 0..1              |                             |
  +----------< orders >---------------+                             |
                 | 1                                                |
                 +----< tickets >-----------------------------------+
                         seat_id (FK), concert_id (FK), checked_in_by -> users

users(id, email, password_hash, full_name, role customer|staff|admin, ...)
concerts(id, title, artist, starts_at, status draft|on_sale|sold_out|cancelled|completed, ...)
zones(id, concert_id, name, price, capacity)          -- ticket tiers
seats(id, zone_id, row_label, seat_number, status available|held|sold, held_until, reservation_id)
reservations(id UUID, user_id, concert_id, status active|converted|expired|cancelled, expires_at)
orders(id, order_number, user_id, concert_id, reservation_id, total_amount, status, payment_status, refund_status)
tickets(id, ticket_code, order_id, concert_id, seat_id, status valid|used|cancelled|refunded, checked_in_at)
\end{lstlisting}
\textbf{Key constraints:} unique index on \code{lower(users.email)};
\code{UNIQUE (zone\_id, row\_label, seat\_number)} on seats and \code{UNIQUE (concert\_id, name)} on zones;
\code{orders.order\_number} and \code{tickets.ticket\_code} UNIQUE; \code{orders.reservation\_id} UNIQUE,
so one hold can be paid only once; partial unique index \code{tickets(seat\_id) WHERE status IN ('valid','used')},
so a seat can never have two live tickets; CHECK constraints on every status column, on prices and
capacities ($\geq 0$ / $> 0$), on \code{refund\_amount $\leq$ total\_amount}, and
\code{(status = 'used') = (checked\_in\_at IS NOT NULL)} on tickets; foreign keys as in the diagram
(zones and seats are deleted with their concert). \\
\textbf{Seed data:} \code{python scripts/seed.py} (data in \cpath{scripts/seed_data.json}) creates
3 users (1 admin, 2 customers), 11 concerts with 33 ticket tiers and their seats (20 seats per
row; sold-out tiers get sold seats), and 14 sample orders (\#10001--\#10014) covering the paid,
pending, failed, cancelled and refunded states. It runs in one transaction under an advisory lock
and only inserts missing rows, so running it again changes nothing. Passwords come from
\cpath{SEED_ADMIN_PASSWORD} / \cpath{SEED_USER_PASSWORD}, or are generated and printed once.
\code{--check} validates the JSON without touching the database; \code{--no-sample-orders} skips orders.

user 1 ----< listing >---- 1 category
  id, email (UNIQUE),        id, title, price,        id, name (UNIQUE)
  password_hash, phone       status, seller_id (FK),
                             category_id (FK)
\end{lstlisting}
\textbf{Key constraints:} \cpath{user.email} UNIQUE (a second register returns 409);
\code{listing.seller\_id $\to$ user.id}; \code{listing.category\_id $\to$ category.id}; index on \cpath{listing.status}.\\
\textbf{Seed data:} 3 users, 5 categories, 24 listings (one user with no listings, for the empty state).
\end{example}

\section{How to Run}
\begin{lstlisting}
git clone https://github.com/WEB-FDA-NEU/AI66B---G1---TOPIC-A4---WEB-DESIGN..git concertly
cd concertly/backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env             # then edit DATABASE_URL / JWT_SECRET / SEED_*
createdb concertly
psql -h localhost -U postgres -d concertly -f schema.sql
python scripts/seed.py
uvicorn app.main:app --reload --port 8000
# second terminal, from the repository root:
python -m http.server 5500
\end{lstlisting}
Open \cpath{http://localhost:5500} (app) and \cpath{http://localhost:8000/docs} (API).
Full steps for a new machine are in \cpath{setup.md}.\\
\textbf{Environment variables:}
\cpath{DATABASE_URL} --- PostgreSQL connection --- \code{postgresql://postgres:<password>@localhost:5432/concertly};
\cpath{JWT_SECRET} --- signs login tokens, required --- output of \code{python -c "import secrets; print(secrets.token\_urlsafe(48))"};
\cpath{SEED_ADMIN_PASSWORD}, \cpath{SEED_USER_PASSWORD} --- demo account passwords used by the seed (random and printed once if empty);
\cpath{CORS_ORIGINS} --- allowed frontend origins --- default \code{*};
\cpath{ACCESS_TOKEN_EXPIRE_MINUTES} --- token lifetime --- default \code{60};
\cpath{RESERVATION_TTL_SECONDS} --- seat hold length --- default \code{300};
\cpath{TEST_DATABASE_URL} --- database for pytest, its name must contain ``test'' because the tests drop and recreate every table.\\
\textbf{Known setup problems:} without \cpath{JWT_SECRET} login fails with 500; a password with
\code{@}, \code{\#} or \code{/} in \cpath{DATABASE_URL} must be URL-encoded (\code{@} $\to$ \code{\%40});
on Windows, if \cpath{Activate.ps1} is blocked, run \code{Set-ExecutionPolicy -Scope CurrentUser RemoteSigned} once.
Until the PRs are merged, run \code{git checkout feat/38-admin-dashboard-checkin}; \cpath{main} does not have the backend yet.
